# Единые правила работы с действиями модулей (Row Actions и Bulk Actions)

В данном документе описан стандарт работы с индивидуальными действиями для записей (Row Actions, в меню "три точки") и массовыми действиями (Bulk Actions) в независимых модулях CRM.

## 1. Регистрация межмодульных действий (Action Registry)

Чтобы сохранить независимость модулей, но позволить одному модулю (например, `Tasks`) добавлять действия в другой модуль (например, `Contractors`), мы используем централизованный `ActionRegistry`.

- **ActionRegistry** находится в `frontend/src/modules/registry/ActionRegistry.ts`.
- При инициализации модуля (или в точке входа) модуль вызывает `ActionRegistry.registerAction(...)`, описывая:
  - `targetModule`: модуль, в который добавляется действие (например, `contractors`).
  - `id`: уникальный идентификатор действия (например, `tasks.create_for_contractor`).
  - `type`: `row` (для одной записи) или `bulk` (для массового).
  - `icon`, `labelKey` (i18n), `permission` (право доступа).
  - `handler`: функция, принимающая контекст (выбранные ID и/или данные записей).

## 2. Настройки действий модулей (Settings)

Все доступные действия (как собственные, так и межмодульные) должны отображаться в настройках модуля (используя хук `useModuleSettings(moduleId)`).

- В настройках можно включать/отключать видимость определенных действий (кроме системных обязательных: Редактировать, Удалить).
- Можно менять их порядок (опционально, если реализован drag-n-drop).
- UI настроек должен включать две вкладки/секции: "Действия таблиц (Row Actions)" и "Массовое редактирование (Bulk Actions)".

## 3. Массовое редактирование (Bulk Actions)

- **UI:** Для массового редактирования используется компонент `BulkActionButton` и `DataTableToolbar` (или специфичный `ModuleToolbar`, например, `ContractorToolbar`), в который прокидывается свойство `bulkActions`.
- **Логика:** При выделении нескольких строк над таблицей появляется кнопка "Массовые действия" или список кнопок.
- **Хуки:** Рекомендуется использовать единый хук, например `useBulkActions(moduleId)`, который получает список действий из `ActionRegistry`, отфильтрованных по настройкам модуля.

## 4. Как применять в новых/существующих модулях

1. В компоненте `XxxTableRow` (для Row Actions) замените жестко заданный список `DropdownMenuItem` на динамический список.
2. В компоненте `XxxToolbar` или `XxxPage` добавьте поддержку свойства `bulkActions`.
3. Убедитесь, что действия корректно получают данные (ID строки или массив ID) и вызывают соответствующий обработчик.
4. Проверьте права пользователя (`usePermission`) — действия, на которые нет прав, не должны рендериться или должны быть задизейблены.

## 5. Запуск миграции
Для применения этих правил необходимо:
1. Создать `ActionRegistry`.
2. Создать хуки `useModuleActions` и `useBulkActions`.
3. Отредактировать компоненты таблиц (`TableRow`) и тулбаров (`Toolbar`) во всех модулях.
